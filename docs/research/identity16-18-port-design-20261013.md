## Selected contracts: two distinct routes

Both routes use N=65536, 32768 complex slots, dense H=2048, input level 2
with scale 2^40, and output level 20 with scale 2^40. The 18 usable circuit
levels refer to the output chain above the reserved input/StC portion; they
are not the numeric output level. The recorded reference correctness gate is
maximum complex error <= 2^-18, with precision bits defined as
`-log2(maximum_complex_error)`. This differs from Cheddar's SNR metric.

## Algorithm and actual modulus schedule

The Identity16 entry is StC-first EvalRound. First, dense StC maps the
level-2 input into coefficients and consumes Q2 and Q1. ScaleDown then brings
the input to the reference's level-0 scale/message-ratio contract. Entry KS
and centered ModUp produce a proper subring branch and a dense bypass branch.
The low-precision CtS and Mod1 branch estimates the integer lift; the bypass
provides the high-precision return. Finish subtracts the integer correction
from the nonlinear result, combines real/imaginary channels, evaluates bypass
CtS, and adds the two returns in matching units.

For selected joint, the exact temporary prime generated by
`rlwe.GenModuli(LogNthRoot=17, [53,53], nil)` is
`qExtra=9007199255658497`. The nominal 53-bit generator argument is not a
license to substitute any approximately sized prime.

| Joint stage | Input basis/level | Output basis/level | Secret |
| --- | --- | --- | --- |
| Dense StC | Q[0:3], 2 | Q0, 0 | dense |
| ScaleDown and entry | Q0, 0 | Q0, 0 | dense -> subring |
| Proper ModUp | Q0 | Q32 + qExtra, 32 | subring |
| Dense bypass fork | lifted main Q32, 31 | main Q32, 31 | subring -> dense |
| M1 Subring Prefix | Q32 + qExtra, 32, no P | main Q32, 31 | subring |
| M2 LCR + AKS | main Q32, 31, P5 for key arithmetic | main Q32, 31 | subring -> dense |
| M3 ordinary factor | main Q32, 31 | Q31, 30 | dense |
| M4 ordinary factor | Q31, 30 | Q30, 29 | dense |
| Mod1 | level 29 | level 20 | dense |
| Bypass and finish | independently bound bypass basis | level 20 / scale 2^40 | dense |

M1 does not conserve its physical input level: it removes qExtra. The
constructor's CtS `LevelQ=31` names the main chain ceiling, not the proper
branch's physical input level 32. M2 is the level-conserved factor.
This agrees structurally with Cheddar's current OverModRaise design; the
parameter values, first width, and scaling contract differ.

Ordinary raises to level 31, switches through the native ephemeral path,
and consumes three ordinary CtS levels to reach Mod1 level 28. Its
degree-30 polynomial plus DA3 consumes eight Mod1 levels to reach 20.
Do not manufacture a subring prefix or low-q0P entry for this route.

## Scaling binding and Grafting

Keep three concepts separate: physical value gain, ciphertext scale, and
the modulus removed by each arithmetic step. A metadata scale assignment
is only correct when the corresponding physical-unit change is derived.

The selected joint binding explicitly validates:

- StC physical gain = 1/64; intermediate scale log2=37.49017137195595,
  output scale log2=32.
- Bypass physical gain = 0.25.
- CtS gain * K * QDiff = 1, with
  QDiff=4398044938241 / 2^42 = 0.9999996423723587.
- ScaleDown ends at level zero. Its integer multiplier and the ModUp
  scale-up are positive powers of two in the selected binding.
- Power-basis scale lift x2 is value-preserving; it is not the Mod1
  output gain and cannot be replaced by `SetScale`.

The actual refresh ModUp scales toward Mod1 scale / message ratio,
`2^(58-10)`, not the application's `2^(40-10)`. The polynomial's
`LogDefaultScale` field is the Mod1 internal log scale in this construction.
Trace this from the native constructor and execution, rather than inferring
from the field name.

The polynomial finish uses the selected reference's explicit correction
gain `K * QDiff * 0.25`. Its restored scale/level must match the bypass
before addition. Cheddar can use a native fused expression if physical
units, reference rounding, depth, and accepted output error are preserved.
Reference fusion and Cheddar kernel fusion are separate decisions.

Cheddar cites Grafting for enhanced rational rescaling and represents mixed
main/terminal bases in Parameter/NPInfo. This does not remove transform gains,
message-ratio binding, Mod1 QDiff corrections, or bypass alignment.
The selected 64-bit chains can first be represented by ordered main primes
with one consumed prime per level and an independent temporary terminal prime
for joint M1. This makes mixed-base rational scheduling unnecessary for these
new profiles; it does not justify removing Cheddar's existing rational
rescaling machinery or claiming LCR is equivalent to Grafting.

## Cheddar philosophy and reuse map

Cheddar optimizes device arithmetic and global-memory traffic through merged
operations, specialized NTT, double hoisting, and fused ModDown/rescale
epilogues. Port the selected arithmetic contracts into this execution model.
Go evaluator object graphs and allocation/copy patterns are not the GPU design.

| Required behavior | Native reuse | Narrow change / proof obligation |
| --- | --- | --- |
| Exact chain and key ceiling | Parameter, NPInfo, NTTHandler, ModSwitchHandler | Q32/P5 ordered chains, output level 20, independent qExtra |
| Dense StC at input level 2 | EvalSpecialFFT elementary matrices, StripedMatrix, LinearTransform | explicit two-factor scales; decouple current StC-after-Mod1 defaults |
| ScaleDown | Context level reduction, scalar multiply, rescale | match reference integer rounding and target scale |
| Entry | EntryGadget, EvaluationKey, GPU key generation | H=40/ext8/sigma=3.2, exact digit count and entry identity |
| Proper/bypass ModUp | centered single-prime lift, NTT, ordinary KS/hoisting | two device-resident branches; preserve subring branch before dense KS |
| M1 | fused SubringPrefixKernel plus native Rescale | compile-time 8-term specialization for width 3; preserve 16-term path |
| M2 | LCROperator, LCRDiagonalAccumKernel, AKSKeyMap, shared centered CRT | re-encode selected M2; prove small-component range on the new low limbs |
| M3/M4 and ordinary CtS | StripedMatrix, LinearTransform, HoistHandler | exact supports and canonical bases; explicit scale per factor |
| Bypass CtS | same LinearTransform and elementary CtS components | independently bound factors, exit key and gain; optimized ordinary backend |
| CosDiscrete and DA | EvalPoly, BasisMap, AXYPBZ, native multiply/relinearize/rescale | selected coefficients/intervals, x2 basis lift, precision-aware pruning |
| Finish | Context Add/Sub/MultImaginaryUnit, AXYPBZ when compatible | correction units and level alignment; fuse only after equivalent reference |
| Measurement | existing paired benchmark and ProfileBoot event callbacks | selected-route end-to-end seam; asynchronous stage intervals |
| Memory | RMM, compact plaintexts, private per-evaluator scratch | level-specific keys and peak-live budget before full allocation |

The M1 kernel currently unrolls 16 terms, and the constructor restricts width
4. Secret sampling hard-codes stride 16/H=256 for MEBOOT. These are qualified
Phase 1 contracts, so use explicit profile-bound extension/weight rather than
changing global defaults. For width 3, its eight automorphisms must fix the
extension-8 secret; validate actual Galois residues.

LCROperator reconstructs at most two Q limbs for uint64_t. With selected
joint Q0/Q1, the centered reconstruction range is approximately 2^74.
This is a bound on supported integers, not proof that the post-M1 components
fit. Integer ModUp scaling, inverse-NTT coefficient growth, encoded diagonal
norms, prefix summation, and rounding must enter the bound. Preserve the
bounded/single-digit fast path only after an independent coefficient oracle
and a conservative bound establish eligibility. If it fails, a broader CRT
or decomposition change is a separate measured choice, never a silent fallback.

EvalPoly's default zero threshold is 1e-9. Do not apply that threshold blindly
to the selected degree-62/30 CosDiscrete vectors. Both polynomial input
interval/offset and normalization must match, not just coefficient count.
Keep the native compiled evaluation tree where its scale schedule works;
add narrowly scoped per-basis scale support if x2 cannot be represented.

Parameter's default scale schedule is also not the selected contract:
it computes `scale[i] = sqrt(scale[i-1] * removed_modulus[i])`.
With a 2^40 base scale, joint's nominal 33/27-bit low primes give approximately
36.5/31.75-bit defaults at levels 1/2, rather than the required 40-bit input
scale. Bind explicit selected input, intermediate and output scales at the
prepared plan/encoding boundary; do not reuse GetScale blindly or alter all
existing parameter defaults. Match actual rounding when returning to the
application scale.

Canonical dense bases describe rotation residues, not the number of live
baby-step buffers. Native LinearTransform builds sparse support maps and
gates fused paths on actual decomposition and baby-index counts. Audit the
selected support maps against its 16-decomposition/128-baby-index fused
specializations. Keeping a global fusion flag enabled is insufficient if the
selected shape takes a generic fallback; expose actual path selection during
diagnostics and measure it.

Reference planned joint keys and retained matrices total
15,402,532,864 bytes (~14.345 GiB) before runtime scratch. Ordinary totals
15,360,589,824 bytes (~14.305 GiB). These CPU-reference payload estimates are
not Cheddar GPU peaks: GHS/hybrid key containers and plaintext ownership differ.
They make a pre-allocation budget essential on the 16 GiB RTX 5060 Ti.
Separate routes into serial preparations; share main/aux polynomial storage,
use existing compact plaintext support, and release preparation-only objects.
Do not reduce Q/P, precision, or output depth to fit memory.

## Performance contract and unresolved evidence

Performance is an acceptance gate, not something this design proves.

1. Freeze and rerun existing 64-bit low-q0P and retained 32/64-bit routes
   before implementation. Retain the Phase 1 baseline of ~96.12 ms only as
   historical context; new runs use current clocks and binaries.
2. Establish native-composition controls for each selected route using the
   exact same arithmetic, levels, precision, keys, and input distributions.
   Only the fusion/scheduling being measured changes.
3. Measure selected joint versus selected ordinary using common slot values,
   common dense secret coefficients and independent route-specific encryption
   under their different bases. Ciphertexts/key containers are not identical.
4. Compare retained old routes before/after on their unchanged contracts.
   The old route returns fewer usable levels and cannot be the sole baseline
   for the new 18-level route.
5. Require median optimized/control ratio <=1.00, with a paired 95% confidence
   upper bound <=1.03 as a measurement uncertainty limit, not permission for
   a measured slowdown. Apply this independently to host and GPU timings;
   inconclusive runs need more samples. Keep median/p95, confidence intervals,
   stage times, precision, output levels and peak-live memory together.
6. Target selected joint <= selected ordinary latency under the common
   identity contract. A failure is a performance blocker/characterization,
   not a reason to alter the reference profiles or omit the bypass.

Use five warmups and at least 30 timed calls per route per run, three
independent paired runs, alternating order, serial GPU work and no stage
synchronizations in production. Preparation, encryption and key generation
are separately reported. Steady-state timed execution contains no intermediate
host transfer; diagnostic downloads run outside it. Only optimize actual
measured hot paths. Nsight is optional if installed; do not invent occupancy
or bandwidth measurements from CUDA event intervals.

Open evidence obligations are exported stage fixtures/scales, the LCR range
proof, polynomial-tree compatibility, and actual peak allocation/latency.
The initial profile equivalence test proves none of those.
