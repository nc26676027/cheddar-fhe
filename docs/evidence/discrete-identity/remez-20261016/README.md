# Lattigo Remez six-bit campaign

Selected profile: degree 63, argument `(2*I+1)/43`, affine encoding
`48/1032`, dense application secret, input scale `2^49*1032`,
digit scale `2^32`, baby step 16, two Thrifty cubics with one rescale each.
Output is L20 at scale `2^40`. This saves one level and has higher latency
than the recorded degree-95 L19 route.

## Mathematical and source evidence

- `direct6-certificate.json` certifies the final binary64 coefficient file
  over all 44 cells `I=-22..21`, including each full `+/-2^-12` interval.
  It excludes encrypted evaluation noise.
- `reference-scan.json` is an independent 100-digit Clenshaw scan.
- `certificate-tests-selected.log` checks the exact interval certificate,
  argument-map consistency, manifest/fixture hashes and retained five-bit behavior.
- `reference-tests-selected.log` contains the six independent arithmetic-reference tests.
- `lattigo-source-provenance.json` identifies the vendored module and records
  comparison with upstream v6.1.1. The Remez core differs only by two comments.
- `degree47-bit0-probe.json` is a partial one-bit experiment, not a complete
  six-bit profile or a formal global lower-bound certificate.

## Encrypted and performance evidence

- `all-cells-selected.log`: final baby-16 profile, all 44 signed cells and
  their centers/boundaries; independent per-bit oracle, reuse and aliasing.
- `all-cells.log` and `all-cells-b32.log`: earlier baby-8 and baby-32 variants.
- `d95-key{1,2,3}.log`: degree-95 comparison, three fresh keysets and 30
  timed calls each, five warmups and five instrumented profiles per keyset.
- `d63-key{1,2,3}.log`: degree-63 automatic baby step 8 with the same protocol.
- `b16-pilot-key1.log`, `b32-pilot-key1.log`: ten-call tuning probes.
- `selected-key{1,2,3}.log`: final baby-16 qualification, three fresh keysets,
  90 timed calls, full-slot precision, integer residual, aliasing and live
  allocation checks.
- `measurements.md`, `comparison.json`: checked aggregation, generated by
  `python3 docs/evidence/discrete-identity/remez-20261016/summarize.py`.
- `inspect_tree.py`, `tree-structure.json`: static product counts derived from
  the frozen evaluator, separately labeled from GPU measurements.
- `profile-build-bindings.json`, `selected-build-bindings.json`: separate
  initial/final binary and source hashes.
- `parameter-audit-final.json`: exact frozen Q/P and entry-domain reuse, complete
  per-prime modulus and scale ledger, and coefficient/certificate hashes.
- `gpu-environment.txt`: GPU, driver, CUDA compiler and WSL kernel.

The initial comparison binary predates the optional baby-step parameter.
The legacy default tree remains identical. Final-build confirmation is
recorded separately in `legacy-final-key1.log` and `selected-final-key1.log`.
These adjacent final-build runs measure 544.238 ms and 620.154 ms GPU medians,
respectively: the six-level route is 13.95% slower while retaining one more
application level.

## Regression and review

`regression.log` records the full retained CTest regression, using timeout
600 seconds and serial execution. As in the previous accepted campaign,
`basic_test` is excluded for its documented preexisting timeout.
The separately recorded Python arithmetic/certificate tests and Go vet
also form part of validation.
All 15 retained CTest targets pass in 972.05 seconds. The five certificate
tests, six arithmetic-reference tests and Go vet also pass.

Parallel Standards and Spec reviews found no remaining actionable issues.
The initial argument-map and manifest-binding findings were resolved with
explicit affine fields in the profile factory and a CMake check against the
passing continuum certificate's SHA256. The final baby-step choice is 16;
the reviewer inspected the common supported baby-step mechanism.
