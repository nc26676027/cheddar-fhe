# Phase 1 acceptance

Run in Linux/WSL with CUDA 12.8 or a compatible toolkit, a supported GPU,
CMake >=3.24, and the normal Cheddar dependencies plus `zlib1g-dev` for the
compressed independent Golden fixture:

```bash
bash unittest/tools/run_phase1_acceptance.sh
```

The script builds current sources and runs all seven test binaries serially.
The basic binary is scoped to `AutonomousModSwitchOperations` (all parameter
profiles); the six extension binaries run their complete suites. The full
basic arithmetic/encoding suite is outside this Phase 1 acceptance scope.
Logs, GoogleTest XML, exact commands, environment, the working-tree patch and
fixture SHA-256 are saved in `.scratch/phase1-acceptance/logs/`. Tests with
unsupported parameter sets can skip; inspect the XML rather than treating
every declared test as an executed pass. CTest also registers these binaries.

After the suite completes, `python3 unittest/tools/verify_golden_guard.py`
temporarily flips a later-slot imaginary sign in the build copy of the fixture,
requires the matrix test to reject it, and restores the original bytes. Run this
serially with GPU tests; the source fixture is never modified.

`python3 unittest/tools/summarize_phase1_acceptance.py` checks that the required
32/64-bit CtS and MEBOOT bootstrap cases actually ran, distinguishes successful
tests from unsupported-profile skips, and writes execution/error/SNR statistics
to `.scratch/phase1-acceptance/summary.json`.

## Independent Golden reference

The binary fixture is generated by the Go `paper1-meboot` module's independent
Lattigo DFT implementation, not by the Cheddar planner. From that module:

```bash
go run /absolute/path/to/cheddar-fhe/unittest/tools/export_meboot_golden.go \
  -output /absolute/path/to/cheddar-fhe/parameters/meboot_golden_4434.bin.gz
```

The exporter calls `dft.MatrixLiteral.GenMatricesSlice(16, 128, stage, 1)` for
`HomomorphicEncode`, `RepackImagAsReal`, logSlots 15, widths `[4,4,3,4]`, four
single-factor levels. Go distributes the normalization as `1/16` per factor;
the C++ planner's unnormalized coefficients are multiplied by that factor for
comparison. Every real and imaginary component, including signs and zeros,
is compared at complex absolute tolerance `1e-12` for both word types.

The gzip payload is little-endian: eight-byte magic `MEBCTSG1`, uint32 slot
count, uint32 stage count, then for each stage a uint32 diagonal count and,
for each sorted diagonal, a uint32 rotation offset followed by 32768 pairs
of IEEE-754 binary64 real/imaginary values. The fixture contains 3,047,424
complex coefficients. Gzip makes this complete fixture smaller without
sampling. No floating-point byte identity between Go and C++ is claimed;
the serialized fixture is pinned by SHA-256 and numerical equality is tested.

See `parameters/meboot_golden_4434.manifest.json` for the reference revision,
source hashes, fixture hash and generation precision.

## Precision and latency target regression

```bash
bash unittest/tools/run_meboot_quality.sh
```

This rebuilds and runs the sparse-secret, centered-CRT and single-prime
ModUp regressions,
the six extension suites plus the paired 32/64-bit
benchmark, retaining earlier acceptance logs. The paired benchmark reuses
the same input ciphertext/secrets/keys, warms up five times and alternates
30 measured executions per path. Its precision assertion compares against
standard Basic with a 1 dB regression alarm. The summarizer additionally
requires the MEBOOT median host latency to match or beat Basic.

The benchmark records host/CUDA-event timings, SNR, maximum complex error,
public-metadata used-key payload, and separately timed M1–M4 stages. Used-key
payload excludes matrix/scratch/allocator memory and reflects keys provisioned
in the shared store. For whole-device sampled memory, record NVML telemetry
separately and run `summarize_meboot_memory.py` against the final evidence
directory; this is not an exact allocation-peak measurement.

## Complete Bootstrap profiling

```bash
bash unittest/tools/run_bootstrap_profile.sh
```

This runs the paired 32/64-bit benchmark with `CHEDDAR_BOOT_PROFILE=1`,
five warmups and 30 measurements per path. `BootContext::ProfileBoot` marks
the actual BootImpl with pre-created, ordered CUDA events. It synchronizes
only before/after the complete operation, not between stages. The output
covers ScaleUp, ModUp, Trace, CtS, real/imaginary split, both EvalMod calls,
recombination, StC, finalization and temporary release. Normal Boot calls
do not record events.

The benchmark checks exact profiled/unprofiled output residues and metadata,
and that the stage intervals account for the total. The profile summarizer
reports mean stage GPU intervals and percentages, profiled/unprofiled totals,
and observed instrumentation-related timing changes. GPU event intervals can
include submission gaps; host submission intervals include implicit CUDA
stalls and are not exclusive CPU time. This is phase profiling, not a Nsight
kernel/occupancy or bandwidth analysis. Full-packing measurements use Trace
with one accumulation; other boot variants have different stage sequences.

Evidence is saved in `.scratch/meboot-performance/bootstrap-profile/final/`.

## StC fixed-input differential benchmark

```bash
cmake --build build --target stc_tuning_test -j 4
build/unittest/stc_tuning_test --gtest_output=xml:stc-tuning.xml > stc-tuning.log
python3 unittest/tools/summarize_stc_tuning.py stc-tuning.log
```

The benchmark uses the real MEBOOT StC start levels for each word size,
five warmups and 30 rotating-order samples per configuration. Configuration
0 uses the original evaluator with BS8; configuration 1 uses verified compact
plaintexts with the same BS8 schedule and keys; configuration 2 explores BS16.
The default remains BS8. Configuration 1 must match every ciphertext residue
of configuration 0, as well as its scale, basis and slot count.

Compaction verifies every encoded RNS word before using a block representative.
Nonperiodic or inexactly repeating encodings retain the full plaintext path.
Full plaintext buffers also remain available for MinKS, so compact tables
reduce evaluation reads but add preparation-time storage. This benchmark does
not measure allocation peaks or replace complete Bootstrap regression and
profiling.
